## 1. 一句话结论

> 本节是 T-001 前的实施基线，保留用于对照；最终状态见 §5、`02 §9 VERDICT: PASS` 与 `docs/adr/0006-runtime-i18n.md`。

当前仓库**已经有完整的中英资源层和组件级 `useTranslation`**，但产品层没有“可切换”的运行时：`i18n` 固定 `zh-CN`，`UiStore` 只持久化主题，原生菜单、窗口标题、另存为默认文件名、About 窗口标题全部硬编码中文，`packages/editor-core` 非测试 `.ts` 仍有 92 行含中文（2 行注释、5 行解析默认值、6 行错误卡文案、79 行直接 DOM/可访问文案；90 行最终可见/可访问），日志时间/更新日期使用系统 locale。

推荐方案是：**把语言当作一种 UI 偏好，由现有 `UiStore` 单一持久化；新增一个 `LocaleController` 作为唯一运行时协调器；前端仍是唯一文案源，Rust 只作为原生外壳的“投影渲染器”接收类型化 `NativeShellLabels` 并重建菜单/标题；编辑器内核通过 CM6 Facet 接收 `EditorUiCopy`，不引入第二套 i18n。** 默认语言保持 `zh-CN`，不新增依赖、不新增数据表、不引入 `i18next-browser-languagedetector` 或 `tauri-plugin-store` 的第二套存储。

## 3. 当前链路与目标链路

### 3.1 当前链路（证据）

```text
启动 main.tsx
  -> import "./i18n"
  -> i18n.init({ lng: DEFAULT_LANGUAGE = "zh-CN", resources, ns: [...7] })
  -> AppShell -> WorkspaceLayout / EditorPage / AboutWindow
  -> useTranslation(...) 读取 zh-CN
  -> 没有 changeLanguage 入口；UiStore 只读 qingmo.ui.theme

原生菜单
  -> tauri::Builder.menu(build_menu)
  -> menu_layout(platform) 返回 &'static str 中文标签
  -> build_submenu -> MenuItem / CheckMenuItem
  -> on_menu_event 只处理已有 action id

窗口标题
  -> document_open -> open_path_in_new_window -> window_title_for(path) = "{name} — 青墨"
  -> document_save_as -> window_title_for(path)
  -> open_about -> ABOUT_WINDOW_TITLE = "关于青墨"
  -> document_save_as -> set_file_name("未命名.md")

编辑器内核
  -> createEditorState -> livePreview -> widgets.ts / specs.ts / block widgets
  -> 92 行含中文（2 注释/5 解析默认/6 错误卡/79 直接 DOM；90 行最终可见）直接写在 packages/editor-core

格式化
  -> LogDialog.formatTime -> Date.toLocaleTimeString([])  // 系统 locale
  -> UpdateDialog.formatDate -> Date.toLocaleDateString() // 系统 locale
  -> StatusBar.formatSize / LogDialog.formatSize         // 两份实现
```

### 3.2 目标链路

```text
启动
  -> UiStore 读取 qingmo.ui.theme + qingmo.ui.language（非法/缺失 -> zh-CN）
  -> i18n.init({ lng: UiStore.language, resources, ns: 从 resources 动态派生 })
  -> LocaleController.start()
       -> i18n.changeLanguage(language)
       -> document.documentElement.lang = language
       -> buildNativeShellLabels(language)
       -> IpcPort.appApplyLocale({ language, labels })

切换（菜单/命令面板）
  -> MENU_ACTIONS.languageZhCN / languageEn 或命令 language.zh-CN / language.en
  -> uiStore.setLanguage(next)（唯一持久化点）
       -> LocaleController（订阅者）串行 apply
  -> React useTranslation 自动重渲染
  -> Rust ShellLocale 保存 language + labels
       -> app.set_menu(build_menu_for(platform, labels, language, livePreview))
       -> 更新所有文档窗口标题 / About 标题
       -> Save As 默认文件名使用 labels.untitledFileName

多窗口
  -> 任一窗口写 localStorage
  -> 其他窗口 storage 事件 -> UiStore.syncFromStorage()
  -> 各自 LocaleController 应用 i18n（不重复写回）
  -> Rust app_apply_locale 幂等：language + labels 相同则直接返回

编辑器
  -> EditorPage -> useEditorLocale(session)
       -> session.applyPlaceholder(t("editor:empty.placeholder"))
       -> session.applyUiCopy(buildEditorUiCopy(language))
  -> CM6 Compartment / Facet 重配置
  -> livePreview cacheKey 含 uiCopy 语言 -> Widget 重绘
```

关键约束：

1. **文案单一源**：所有用户可见自然语言只在 `apps/desktop/src/i18n/locales/{zh-CN,en}.ts`；Rust 不保存第二份完整菜单文案，只保存前端投影过来的 `NativeShellLabels`。
2. **状态单一源**：`UiStore` 是 UI 偏好唯一持久化点；`LocaleController` 是唯一运行时协调器；React 组件只消费 `useTranslation` 与 `useEditorLocale`。
3. **原生外壳是投影**：Rust 的 `ShellLocale` 只缓存最近一次合法投影；`app_apply_locale` 必须幂等，重复调用不重复重建。
4. **默认安全**：缺 key/非法值/localStorage 被禁 -> `zh-CN`；原生菜单应用失败 -> UI 仍切换，菜单可能保持旧值或无/部分菜单，记录日志，不崩。
5. **不新增依赖/表**：不引入 language detector、store 插件、数据库表或 settings 文件。

## 6. 数据模型 / 配置 / 接口

### 6.1 数据模型

**不新增数据库、不新增表、不新增迁移。** 语言只存在于：

```ts
interface UiSnapshot {
  theme: "light" | "dark" | "system";

  language: "zh-CN" | "en";

// localStorage（唯一新增键）
"qingmo.ui.language": "zh-CN" | "en"
```

Rust 只保留进程内状态，不落盘：

```rust
enum AppLanguage { ZhCn /* "zh-CN" */, En /* "en" */ }
```

- 新增 `INVALID_LOCALE` 是错误码枚举的追加；旧 `errors.ts` 镜像需同步，契约测试防漂移。
- 不改变保存/关闭/更新/编辑器的数据语义。

## 9. 风险与回滚摘要

| RK-ID | 风险 | 影响 | 缓解措施 | 回滚方式 |
|---|---|---|---|---|
| RK-001 | 原生菜单重建在主线程/菜单打开时执行 | 菜单短暂无响应/崩溃 | 由 IPC 命令在菜单事件返回后重建；best effort，失败可能无/部分菜单；不提交 state，下一次重试并记录 | 回退 T-005；恢复静态菜单 |
| RK-002 | 前端标签与 Rust DTO 漂移 | 菜单出现空/旧文案 | 生成类型 + `validate()` + 长度/控制字符校验 + 双语文案测试 | 回退 `app_apply_locale`；静态菜单 |
| RK-003 | 多窗口/快速切换乱序 | 旧语言覆盖新语言 | LocaleController 串行队列 + 持久化 guard（null 不覆盖）+ 前后双检 + Rust 幂等比较 | 回退 T-008/T-005 |
| RK-004 | `UiStore` 快照扩展影响主题消费者 | 主题测试/渲染回归 | 加法字段；更新测试；`useSyncExternalStore` 不变 | 回退 T-003 |
| RK-005 | `EditorSession` 是 CRITICAL，改 placeholder/uiCopy 可能影响保存/IME | 编辑/保存回归 | 只加 Compartment/Effect；不碰文档/保存路径；专项测试 | 回退 T-012/T-013 |
| RK-006 | Widget 重绘性能/布局 | 切换卡顿/文本错位 | cache key 含语言；装饰器只重绘不重建视图；bench/视觉冒烟 | 回退 T-013/T-014 |
| RK-007 | 英文标签更长导致菜单/按钮溢出 | 布局问题 | 长度上限 + 英文 E2E/截图 + 手动菜单冒烟 | 缩短文案/调整布局 |
| RK-008 | `Intl` 输出随 ICU/平台差异 | 测试脆弱 | 用 `Intl` 自身生成期望值；只断言语义 | 回退 T-011 |
| RK-009 | localStorage 被禁用/隐私模式/写入失败 | 偏好不持久 | 内存态仍可切换且不被 guard 回退；不崩；记录 | 无（降级） |
| RK-010 | About 窗口 storage 事件不触发 | About 语言不跟随 | 启动时读 storage；E2E 双页验证；失败则重开窗口 | 回退 T-010 |
| RK-011 | 默认语言改变（若 Q-003 选 OS） | 现有用户/测试行为变化 | 默认保持 zh-CN；OS 检测单独批准 | 改回 zh-CN |
| RK-012 | 文档/README 夸大能力 | 产品承诺不一致 | T-017 同步；AC-012 | 文档回滚 |

回滚原则（必须按顺序，不能把“删键”当第一步）：

1. **先禁用入口并强制默认语言**：移除菜单/命令入口；`LocaleController` 读取语言时临时固定 `zh-CN`（保留 `UiStore.language` 字段，避免类型断裂），确认 UI 与持久化都回中文。
2. **再拆原生投影**：将 `LocaleController` 的 `native` 置空，确认不再调用 `app_apply_locale` 后，回退 Rust 命令/权限/`ShellLocale`。反过来先删命令会让前端调用失败。
3. **然后回退状态层**：同一提交内回退 `UiStore.language` 字段、`qingmo.ui.language` 读取和 `i18n` 动态初始化，避免 `getSnapshot().language` 编译失败。
4. **编辑器按注入点回退**：回退 `T-013`/`T-014` 时必须同时移除 desktop 的 `uiCopy` 注入，恢复原硬编码中文；只回退 `T-014` 会保留默认英文 copy，不能声称“恢复中文”。
5. 不修改文件格式、保存/关闭/更新协议；启动安全中性菜单的 Quit/CloseGuard 已由 T-018 真机验证（`E-051`）。最后再清理 `qingmo.ui.language` 键。
