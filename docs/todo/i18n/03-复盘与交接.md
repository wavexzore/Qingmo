## 1. 复盘摘要

### 1.1 这次真正解决了什么

不是“从零做 i18n”，而是把已经存在但**没有接线**的能力接起来：

- 资源层已经完整（`zhCN`/`en`，7 namespace）；
- 组件已经大多使用 `useTranslation`；
- 主题已经有“`UiStore` 持久化 + 跨窗口 storage + CM6 Compartment”范式；
- 原生菜单已经是声明式 `MenuSpec`，适合数据化。

方案的核心是**复用这些范式**，而不是再造一套：

```text
主题：UiStore -> useThemeService -> themeCompartment
语言：UiStore -> LocaleController -> i18n + 原生投影 + EditorUiCopy Facet
```

### 1.2 如果只记住三件事

1. **语言只能有一个持久化点**：`UiStore` 的 `qingmo.ui.language`。
2. **Rust 不维护第二套翻译**：它只渲染前端传来的 `NativeShellLabels`。
3. **editor-core 不 import i18next**：它只接收 `EditorUiCopy` Facet。

违反任意一条，都会在 3~6 个月后产生“中文菜单 + 英文按钮”“资源 key 缺失但没人发现”“切换语言后 Widget 还是旧文案”的回归。

### 1.3 为什么现在不做“大重构”

- 当前 `EditorSession` 是 CRITICAL，保存/关闭/IME 都在这里；语言只需要“加方法/加 Compartment”，不需要重写。
- 当前 `UiStore` 只有 232 行，扩展 language 的成本远低于新建 store。
- 当前菜单是纯数据 `MenuSpec`，改成 `&str` 借用即可；不需要引入菜单框架。
- 引入 `tauri-plugin-store`/language detector 会带来第二持久化、第二键、迁移和测试复杂度，收益不匹配。

## 3. 现状为什么是这样（历史脉络）

| 阶段 | 产物 | 留下的缺口 |
|---|---|---|
| P0/P1 编辑器 MVP | `i18n/index.ts` + 中英资源 + `useTranslation` | 固定 `zh-CN`，没有切换 |
| 主题功能 | `UiStore` + `data-theme` + `themeCompartment` | 只持久化 theme |
| 菜单功能 | `MenuSpec` + macOS/Windows 双布局 + 结构测试 | label 是 `&'static str` 中文 |
| About/Updater/Logs | 新窗口/新对话框/新文案 | About 只同步 theme；日志/日期用系统 locale |
| Live Preview | `WidgetType` + StateField + 大量中文 UI | 没有 copy 注入点 |

结论：缺口是**演进过程中每个功能各自解决本地文案**留下的，不是一次设计失误。因此修复也应该“按层接线”，而不是推翻重来。

## 4. 踩坑与避免

### 4.1 已识别的坑

| 坑 | 现象 | 避免 |
|---|---|---|
| 第二持久化键 | `i18nextLng` 与 `qingmo.ui.language` 不一致 | 不引入 detector；只认 UiStore |
| 第二文案源 | Rust 菜单/标题与前端资源漂移 | 只接收 `NativeShellLabels` |
| 启动首帧 | Rust 读不到 localStorage，英文用户看到中文 | 中性 title/安全中性菜单 + 首帧投影 |
| 菜单重建重入 | 菜单打开时切换语言，重建导致卡顿/崩溃 | IPC 在菜单事件返回后；同步命令；best effort，失败可能无/部分菜单；不提交 state，下一次重试 |
| 快速切换乱序 | A->B->A 最终停在 B | controller `pending` 合并 + Rust 幂等 |
| StrictMode | 双挂载重复 apply/重复菜单重建 | controller stop/start + Rust 幂等 |
| placeholder 捕获 | 切换后未命名文档仍显示旧 placeholder | placeholder Compartment + `useEditorLocale` |
| Widget 不重绘 | 注入 copy 但 DOM 不更新 | cache key 加 version；Widget eq 比较 version |
| 内部错误中文 | 英文 UI 的 Mermaid 错误框出现中文 | `MermaidRenderError.code` + copy 映射 |
| 格式化残留 | UI 英文但日期中文 | `lib/format` 统一 Intl |
| About 孤岛 | 主窗口英文，About 中文 | About 复用 controller + storage sync |
| 菜单 action 丢失 | About-only 时无接收窗口 | 记录 `NEXT-I18N-006`；主窗口存在时正常 |
| 契约测试先后端 | 只改 Rust 会让 `commands_contract` 扫描前端 `commands.ts` 时变红 | T-004 同批更新前端镜像/错误码/locale key |
| 平台默认 Quit | `Menu::default`/`PredefinedMenuItem::quit` 可能绕过 CloseGuard | 启动即用自定义 `MENU_QUIT`；T-018 实测 Quit/Cmd+Q |
| 测试假绿 | 只比 key 集合，漏 about/logs/复数/插值 | 动态 namespace + `Intl.PluralRules` + 插值集合 |
| 图谱假安全 | `document_save_as` impact=UNKNOWN | 用 `commands/mod.rs`、前端调用、契约测试三重确认 |

### 4.2 实施时最容易犯的错

1. **在 `i18n/index.ts` 里 `import { uiStore }` 后又在 `uiStore.ts` 里 `import i18n`** -> 循环。规则：`uiStore` 只 import `i18n/language.ts`。
2. **在 `EditorSession` 里直接 `i18n.t`** -> 编辑器内核依赖 UI 单例，测试/多窗口失控。规则：只通过 `EditorUiCopy`。
3. **在 `WidgetType.toDOM` 里 `import i18n`** -> 同上。规则：`toDOM(view)` 读 `view.state.facet(editorUiCopy)`。
4. **在 `app_apply_locale` 里先提交 `ShellLocale` 再 `set_menu`** -> 构建失败后状态说“已应用”，下次同请求跳过，菜单永远不更新。规则：先 build/set，再 commit。
5. **把 `MenuSpec` 的 label 改成 `String`** -> 每次构建分配，生命周期复杂。规则：借用 `&'a str`，labels 在命令栈上活到构建完成。
6. **忘记 `set_live_preview_checked` 的新菜单层级** -> 勾选不更新。规则：语言子菜单是“显示”的子菜单，实时预览仍是“显示”的直接项；保留现有查找逻辑并加测试。
7. **忘记 `WindowSessions` 的 pending payload** -> 新窗口还没 `take_pending` 时切语言，标题不更新。规则：`pending_path` + `token_for` 两条路径。
8. **依赖平台默认 Quit 或 `ExitRequested` 兜底** -> Quit 绕过 CloseGuard。规则：启动安全菜单就用自定义 `MENU_QUIT -> request_close`；`ExitRequested` 只作为额外兜底。
9. **把 `document.title` 当成原生标题** -> 可能与 Rust `set_title` 打架。规则：原生标题由 Rust 控制；HTML title 只做中性兜底。
10. **在 `MenuSpec` 测试里写死中文** -> 重构后测试仍绿但英文菜单错。规则：测试传入中英 labels，分别断言结构/标签。

## 5. 维护手册

### 5.1 新增一种语言

1. 在 `i18n/language.ts` 的 `SUPPORTED_LANGUAGES` 加 tag（如 `ja`）。
2. 新增 `i18n/locales/ja.ts`，导出与 `zh-CN` 相同的 namespace。
3. 在 `i18n/index.ts` 的 `resources` 注册。
4. `NativeShellLabels` 当前只有 `languageZhCN`/`languageEn` 两个显示名；新增第三种语言时要加字段并同步 Rust 菜单子项，不能假设自动扩展。
5. `EditorUiCopy` 不需改结构；`buildEditorUiCopy` 自动用新语言。
6. 更新 `Intl.PluralRules` 测试；如语言有 RTL，先做布局（超范围）。
7. 原生菜单语言子菜单加一项（`MENU_LANGUAGE_*` + `menu_layout` + `MENU_ACTIONS`）。
8. 更新 E2E/手工矩阵。
9. **需要人工批准**：新语言是产品行为变更。

### 5.2 新增一个用户文案

1. 只加到 `apps/desktop/src/i18n/locales/zh-CN.ts` 和 `en.ts`（同 key）。
2. 组件用 `t("ns:key")`；不要写 JSX 字面量。
3. 编辑器 Widget 加到 `EditorUiCopy` + `buildEditorUiCopy` + 默认 copy。
4. 原生菜单/标题加到 `NativeShellLabels` + `menu` namespace + Rust 字段/测试。
5. 跑 `pnpm test i18n`（key/插值/复数）与相关组件测试。

### 5.3 新增一个菜单项

1. `NativeShellLabels` 加字段（或复用已有）。
2. `menu_layout` 加 `MenuEntry`。
3. `MENU_ACTIONS`/`commands.ts` 加 action id（如果是 webview action）。
4. `WorkspaceLayout` switch 加处理；或 Rust `on_menu_event` 直接处理。
5. 菜单结构测试：中英标签、快捷键、handler 覆盖、action 唯一。
6. 如涉及原生文案，更新 Q/文档。

### 5.4 新增一个 Widget

1. 在 `EditorUiCopy` 加分组/字段。
2. 在 `buildEditorUiCopy` 加 `t` 映射。
3. Widget 构造函数接收 `copy` 或 `toDOM(view)` 读 facet。
4. `eq` 比较 `copy.version`；cache key 已含 version。
5. 不要 import i18next；不要写中文字面量。
6. 加中英 textContent/title/aria 测试。

### 5.5 修改持久化/契约

- 新增 localStorage 键：必须人工批准；优先复用 `UiStore`。
- 新增 IPC/权限/错误码：必须人工批准；更新 `contract.rs`、`commands.ts`、capability、generated、contract/security 测试。
- 新增 DTO：`export_bindings.rs` + `check-generated.sh`。
- 不得跳过 `commands_contract`/`security_config`。

## 6. 回滚手册

| 症状 | 最小回滚（按顺序） | 验证 |
|---|---|---|
| 菜单重建崩溃/卡顿 | 先 `native:null`，再回退 `app_apply_locale`/`menu_layout`，恢复静态菜单 | 启动/编辑/关闭正常 |
| 语言切换导致保存/IME 回归 | 回退 T-012/T-013，保留外壳 i18n；先移除 `uiCopy`/placeholder 注入 | `pnpm test editor-session` |
| Widget 重绘卡顿 | 回退 T-013/T-014，并移除 desktop `uiCopy` 注入；否则会留默认英文兜底 | editor-core 测试 |
| About 不同步 | 回退 T-010，About 启动读取 storage | About 手动 |
| 日期格式测试脆弱 | 回退 T-011，组件局部格式化 | UI 手动 |
| 持久化键冲突 | 最后删除 `qingmo.ui.language`；先确保没有代码再读它 | 重启 |
| 全部异常 | revert 功能提交；最后清键 | `pnpm ci:local` |

回滚原则：

1. 无数据迁移，但**不能把“删键”当第一步**；先禁入口/强制默认语言。
2. 先移除调用方（`LocaleController.native`），再删 Rust 命令/权限；反过来会出现 invoke 失败。
3. `UiStore.language` 字段、i18n 动态初始化、读取代码必须在同一提交回退，避免编译/类型断裂。
4. 编辑器回退要同时移除 desktop 注入；只回退 T-014 会保留默认英文 copy。
5. 不回退用户文件/保存协议；启动安全中性菜单 Quit 待 T-018 真机验证。
