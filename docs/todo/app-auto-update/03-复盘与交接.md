## 1. 最终结论

本功能已从“设计准备”推进到**可本地验证、可本地出包**的实现：官方 `tauri-plugin-updater` 2.14.0 Rust API 已接入，Rust `UpdateManager` 是唯一状态机，前端 `UpdateController` 只镜像快照/事件；安装前复用 `SaveCoordinator.flush("close")`；`CloseGuard` 用同一 Mutex 提供安装门闩；命令面板 + 非模态横幅 + 对话框已可用，发布说明按纯文本渲染；E2E 用零网络 `FakeUpdatePort` 覆盖检查/下载/进度/保存阻断/冲突/错误。本地 universal 构建已通过 Developer ID 签名、App 公证、DMG 单独公证/stapling、updater minisign 签名与 `latest.json` 验签（C-026）。

仍**不是可对外宣布已完成的状态**：`T-011` 本地发布链路已完成，GitHub Actions 发布路径已按本地优先决策停用（`release` Environment/secrets 已删除）；`T-014` 的 macOS Apple Silicon/Intel 真机安装/重启冒烟尚未执行。当前 `VERDICT: PARTIAL`；不得对外宣称自动更新已通过公开分发验收。

核心收益是：把“更新”从一句蓝图目标拆成可实施、可测试、可回滚、可审计的任务，并把关闭/安装竞态、保存冲突、签名版本绑定、权限面等高风险点前置到测试。遗留风险主要是：清单未签名/冻结、私钥丢失/泄露、无百分比灰度、首版前用户无法自动更新、下载包常驻内存；详见 `04 §17` 与 `02 §9`。

## 5. 回滚指南

> 当前没有已发布版本，以下为**实施后**可执行的回滚手册；发布前需在测试仓库演练。

| 场景 | 回滚动作 | 验证命令 | 风险 |
|---|---|---|---|
| 代码缺陷（未发布） | `git revert <commit>`；不 force push main | `pnpm ci:local` | 低 |
| 发布 workflow 配置错误 | revert workflow；删除 draft release | `actionlint`；`gh release view` | 低 |
| 已发布但用户未更新 | 标记 `--prerelease --latest=false`（immutable 安全）；非 immutable 可再改 draft | `curl` latest + `check-latest-json` | 中：已下载用户仍可能安装 |
| 用户已安装坏版本 | 发布更高版本 hotfix（不能自动降级） | 新版本 check/install 真机 | 高：必须快速发布 |
| 签名密钥丢失 | 无法签过渡版本；发布手工下载 + 新 key 新通道；承认旧客户端失联 | 手工安装/新版本 | 高：应用内无恢复路径 |
| latest.json 平台键错误 | 撤下 release；修正 action/门禁后重发 | `check-latest-json --no-network` + 在线 | 中 |
| 签名密钥泄露 | 停止发布；安全公告；用旧 key 发过渡版本内置新公钥；之后换新 key | 过渡版本真机更新到新 key 版本 | 高：旧客户端无法撤销 |
| Xcode 证书过期/丢失 | 从 Xcode/钥匙串恢复或重新签发 Developer ID；导出新 `.p12` 到本地 `.release/certs/`；重发 | `codesign`/`notarytool`/`spctl` | 高：发布暂停，已安装用户不受影响 |
| CI secret 泄露（仅在启用可选 Actions 通道时） | 轮换 secret；审计 workflow；最小权限 | 重新跑 release；检查 audit log | 高 |
| 插件/Tauri 不兼容 | 回退 `Cargo.toml` 到 2.13.3；重建 | `cargo check`/`cargo test` | 中 |
| 配置错误（HTTP/降级） | 回滚 `tauri.conf.json`；安全测试 | `security_config.rs` | 高：不得带病发布 |

首选回滚命令：

```bash
# 撤下坏版本（immutable release 下仍可用）
gh release edit vX.Y.Z --prerelease --latest=false

# 非 immutable 仓库可再改 draft
gh release edit vX.Y.Z --draft

# 确认 latest 已回到上一稳定版（断言具体版本，不只看存在）
curl -fsSL https://github.com/<owner>/qingmo/releases/latest/download/latest.json | jq -r '.version'

# 代码回滚（不使用 force push）
git revert <bad-commit>
git push origin main

# 重新构建更高版本
git tag vX.Y.(Z+1)
git push origin vX.Y.(Z+1)
```

不可逆变更：无数据库/用户配置迁移；唯一不可逆是“用户已安装坏版本”，只能 hotfix。

### 6.3 日志与排查

| 场景 | 查看位置 | 判断方法 |
|---|---|---|
| 检查失败 | `tracing` 日志 `update.check.*` | 看 reason（network/timeout/config/platform），不看 URL |

## 7. 已知限制

| 限制 | 影响 | 后续建议 |
|---|---|---|
| 无自动回滚 | 坏版本只能 hotfix | `NEXT-AU-002` 评估备份/回滚 |
| 无百分比灰度 | 坏版本影响全量 | 服务端通道/分段发布（`NEXT-AU-002`） |
| 无用户配置 | 不能记住“跳过版本/关闭自动检查” | 统一 settings（`NEXT-006`） |
| 清单未签名 | 冻结攻击/元数据篡改仍有残余 | TUF/Uptane（`NEXT-AU-001`） |
| 无增量更新 | 每次整包下载 | `NEXT-AU-004` |
| 不支持移动端 | 商店政策/插件不支持 | `NEXT-009` |
| 无遥测 | 无法量化更新成功率 | `NEXT-AU-003`（默认隐私） |
| 仅 macOS | Windows/Linux 用户需手工更新 | `NEXT-AU-007` |
