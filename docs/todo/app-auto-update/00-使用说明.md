# 应用自动更新 — LLM 使用说明

> **功能 ID：** `app-auto-update`
> **用途：** 约束后续 LLM/维护者在多轮会话中安全推进自动更新功能，避免重复实现、越权新增配置/数据表、绕过保存/关闭状态机。
> **适用位置：** `docs/todo/app-auto-update/`

---

## 1. 恢复顺序

每轮开始必须按以下顺序读取：

1. `README.md` 的 `LLM-STATE`；
2. `01-实施计划.md` §6 任务队列与 §12 人工决策记录；
3. `02-实施状态与验证.md` §3 执行日志、§7 Blockers、§8 计划 vs 实际；
4. `05-多轮评审记录.md` 的最新结论；
5. 只有以上状态允许时，才读取/修改代码。

恢复时先运行：

```bash
git rev-parse HEAD origin/main
git status --porcelain
node .gitnexus/run.cjs status
```

若 HEAD、关键调用链或计划已变化，先更新 `01 §13` 和 `02 §8`，再实施。

---

## 2. 审批门禁（硬约束）

以下事项**未经人工明确同意不得实施**：

1. 新增任何用户级配置项（settings 文件、JSON 键、环境变量暴露给用户、localStorage 键）。
2. 新增任何数据表、迁移、SQLite schema 或索引。
3. 新增 `updater:*` JS 权限、放宽 CSP、启用 `dangerousInsecureTransportProtocol`、启用 `allowDowngrades`。
4. 修改 `SaveCoordinator` 的保存状态机、`useCloseGuard` 的关闭语义、`AtomicWriter` 的写盘路径。
5. 把更新私钥、token、证书或任何 secret 写入仓库/日志/构建产物。
6. 对 `main`/`master` force push，或对他人提交 amend。

审批记录写在 `01 §12`（Q-ID）与 `02 §7`（B-ID）。未确认时任务必须标 `blocked`，不得用默认值“先做”。

## 3. 状态枚举

### 3.1 功能状态

`todo | in_progress | blocked | partial | done | rolled_back | cancelled`

### 3.2 任务状态

`todo | in_progress | blocked | done | skipped`

### 3.3 验证状态

`not_run | pass | fail | partial | skipped`

### 3.4 最终 VERDICT

`PASS | FAIL | PARTIAL`

> 本方案当前是“方案交付、未实施”：`02` 的 `VERDICT: PARTIAL` 表示调研/设计/评审完成，实施任务尚未开始，不是“功能已验证”。

---

## 4. 实施协议

### 4.1 每个任务执行前（Pre-Implementation Check）

- [ ] 重新读取任务 `Files` 中列出的文件，确认路径仍存在。
- [ ] 用 GitNexus `context`/`impact` 复查关键符号（至少 `SaveCoordinator.flush`、`request_close`、`app_close_confirm`、`createAppServices`、`createTauriIpc`）。
- [ ] 确认 `UNKNOWN` 风险没有被当成 LOW；Tauri 宏/字符串 invoke 的调用方需用文本测试/契约测试确认。
- [ ] 确认没有新增配置/数据表/权限；如需要，先提 Q-ID 并停下。
- [ ] 若代码已变化，先更新 `01 §13`/`02 §8`，再实施。

### 4.2 每个任务执行中

```text
读取任务 -> 确认依赖 -> 实时校准 -> 限定文件范围 -> 最小切片
-> 运行该任务验证 -> 写 02 日志 -> 更新 01/README 状态
```

禁止：

- 没有证据就标 `done`；
- 跳过依赖；
- 修改 `Files` 之外的文件且不记录原因；
- 复制第二套保存/关闭/配置/错误/命令逻辑；
- 把 `UNKNOWN` 当成安全；
- 在未审批时新增配置项/数据表。

### 4.3 每个任务执行后

- 更新 `README LLM-STATE`；
- 更新 `01 §6` 任务行；
- 更新 `02 §2` 镜像、`§3` 日志、`§4` 命令；
- 失败时记录 `B-###`、失败证据、已尝试方案、下一恢复动作；
- 改动命令/事件/DTO/权限时，同批更新 `contract.rs`、`commands.ts`、capability、生成类型、契约测试。

## 5. 证据规范

“完成”必须绑定至少一种证据：

| 类型 | 示例 |
|---|---|
| 代码路径 | `src-tauri/src/state/update_manager.rs:begin_check` |
| 测试 | `cargo test --manifest-path src-tauri/Cargo.toml update_manager` / `pnpm test -- UpdateController` |
| 命令 | `pnpm ci:local` |
| 配置 | `src-tauri/tauri.conf.json` 的 `plugins.updater.requireSignedVersion=true` |
| 契约 | `COMMANDS.len()==9`、`EVENTS.len()==3` |
| 官方文档 | Tauri updater docs / plugin 2.14.0 source / Tauri CLI 2.12.0 changelog |
| GitHub 参考 | `tauri-apps/plugins-workspace`、`tauri-apps/tauri-action`、`screenpipe/screenpipe` |
| GitNexus | `impact: CRITICAL, affected_processes: ...`（必须附查询） |
| subagent | `explore: 入口 -> ... -> app_close_confirm`（附 session/摘要） |
| 论文/标准 | TUF CCS 2010、Uptane、USENIX Security 2026 |

不要写“已完成”“已验证”而不附文件/命令/日志。

## 6. 本功能特有的不变量

1. **单一保存路径：** 所有安装前保存只调用 `SaveCoordinator.flush("close")`；不得新增 `saveBeforeUpdate`、`forceSaveForUpdate` 等第二路径。
2. **单一关闭决策点：** Rust `CloseGuard`/`app_close_confirm` 仍是唯一入口；只增加同一 Mutex 内的 `installing`/`exiting` 门闩与 `confirm(allow)`，不新增第二套关闭逻辑。更新重启用 `app.request_restart()`（`RESTART_EXIT_CODE`），不调用 `app_close_confirm`。
3. **单一更新状态：** Rust `UpdateManager` 是 phase 权威；前端 `UpdateController` 只镜像 `app://update-state`/`app://update-progress`，不得自己实现第二套 phase 转换。
4. **单一契约源：** `src-tauri/src/ipc/contract.rs` + `apps/desktop/src/lib/ipc/commands.ts` 镜像 + capability + ts-rs 生成 + 契约测试，同批更新。
5. **默认安全：** 签名/版本不匹配、未下载、保存失败、CloseGuard pending、非法状态一律拒绝安装；不自动降级。
6. **默认最小权限：** 不新增 `updater:*` capability；更新网络只在 Rust 侧；CSP 不变。
7. **无新配置/数据表：** MVP 不写 settings/localStorage/SQLite；构建/发布配置新增项需 Q-008。
8. **平台边界：** MVP 仅 macOS universal；使用 Xcode 的 Developer ID 证书签名 + Apple 公证。Windows/Linux 的 NSIS/AppImage、平台键与安装分支统一进入 `NEXT-AU-007`，不得在首版偷偷加入。

---

## 7. 失败与回滚

- 任务失败：`02 §7` 记录 B-ID；不得静默跳过。
- 代码回滚：按 `01 §10.2`；未提交改动用 `git diff`/`git restore`，已提交用 revert（不对 main force push）。
- 发布回滚：撤下/替换 release/latest.json，发布 hotfix；已安装用户不能自动降级。
- 密钥事故：按 `03 §5` 轮换 runbook；先停止发布，再评估旧客户端影响。
