## 1. 实施结论

Qingmo 当前没有任何应用更新能力：没有 updater 插件、没有发布 workflow、没有签名密钥/`latest.json`、没有更新 UI，且版本号分散在 7 处。用户只能手工下载新版本；发布者也没有可重复、可验签的发布链路。

按 2026-10-27 决策，首版**仅支持 macOS universal**，使用 **Xcode 中的 Developer ID Application 证书签名 + Apple 公证**。推荐实施路径是：**Tauri 官方 `tauri-plugin-updater` 2.14.0 的 Rust API**（不引入 JS updater 插件/权限） + **Rust `UpdateManager` 单一状态机** + **前端 `UpdatePort`/`UpdateController` 镜像与编排** + **安装前复用 `SaveCoordinator.flush("close")`** + **GitHub Releases + `tauri-action@1.0.0` + `requireSignedVersion` 的发布门禁**。这是最小安全切片：不新增用户配置、不新增数据表、不改保存状态机；关闭侧只给 `CloseGuard` 增加安装/退出终态，不复制第二套配置/错误/命令逻辑。Windows/Linux 与 deb/rpm/NSIS 不在 MVP 内，统一移入 `NEXT-AU-007`。

明确不做：自动静默安装、自动回滚、stable/beta 用户切换、百分比灰度、自定义 TUF 元数据、移动端自更新、增量更新。它们要么与当前 Tauri 插件能力不符，要么需要新的服务端/配置/数据表，必须先走人工决策。

LLM 应从 `T-001` 开始；`T-011` 已在本地发布范围完成，GitHub Actions 路径按本地优先停用；仅 `T-014` 真机冒烟保持 `blocked`（`B-002`）。

## 4. 目标方案

### 4.1 目标链路

```text
启动
  -> qingmo_lib::run
  -> Builder.plugin(tauri_plugin_updater::Builder::new().build())
  -> manage(UpdateManager)
  -> invoke_handler(9 commands)
  -> RunEvent(CloseRequested/ExitRequested)

检查
  -> UpdateProvider(启动 8s 静默) / CommandPalette(app.checkForUpdates)
  -> UpdateController.check(silent)
  -> UpdatePort.check -> invoke("app_update_check")
  -> UpdateManager.begin_check (phase=Checking, generation+1)
  -> app.updater_builder().build()?.check() (outer timeout 30s)
  -> none: phase=Idle; some: phase=Available + app://update-state
  -> UpdateHost 横幅 / UpdateDialog

下载
  -> UpdateController.download
  -> invoke("app_update_download")
  -> UpdateManager.begin_download (phase=Downloading)
  -> update.download(on_chunk, on_finish) (outer timeout 10min)
  -> 累计 downloaded += chunk; total=content_length; 100ms 节流 app://update-progress
  -> 验签成功: artifact=bytes, phase=Ready + state
  -> 失败: phase=Available, 清 progress, 返回分类错误

安装
  -> UpdateController.install(coordinator)
  -> coordinator.flush("close")
  -> 失败: 阻断，显示冲突/错误
  -> 成功: invoke("app_update_install")
  -> UpdateManager.begin_install (phase=Installing; CloseGuard 门闩在命令层先行)
  -> update.install(bytes) (再次验签)
  -> macOS: app.request_restart() (ExitRequested code=RESTART_EXIT_CODE)
```

### 4.2 设计决策

| D-ID | 决策 | 理由 | 拒绝方案 | 影响任务 |
|---|---|---|---|---|
| D-001 | 采用官方 `tauri-plugin-updater` 2.14.0 Rust API | 官方维护/验签/平台安装；避免自建 | 自建 HTTP/安装器；JS guest | T-003/T-007 |
| D-002 | Rust `UpdateManager` 是唯一 phase 权威 | 单飞/并发/恢复/错误集中；前端只镜像 | 前端状态机；双状态 | T-006/T-008 |
| D-003 | 前端 `UpdateController.install` 是唯一安装编排，内部先 `SaveCoordinator.flush("close")` | 复用唯一保存路径；防止漏存 | 组件直接 install；新增 saveBeforeUpdate | T-008/T-009 |
| D-004 | MVP 不新增用户配置/数据表/localStorage | 遵守 ADR-0001/NEXT-006；避免第二配置源 | settings.json/SQLite/localStorage | T-001/T-009 |
| D-005 | 不引入 JS updater 插件/`updater:*` 权限 | 最小权限；Rust 侧网络不暴露给 WebView | JS guest + capability | T-003/T-004 |
| D-006 | 首版仅 stable 通道 | 静态 latest.json 不支持百分比灰度；beta 需独立发布/端点 | stable+beta UI | T-001/Q-005 |
| D-007 | GitHub Releases 公共 `latest.json`（Q-001 已确认） | 零服务端、HTTPS、与 tauri-action 匹配 | 私有 token/自建源 | T-011 |
| D-008 | 开启 `requireSignedVersion`；禁止 HTTP/降级 | 绑定清单版本到签名；防经典降级重放 | 只验 artifact；`dangerousInsecureTransportProtocol` | T-003/T-011 |
| D-009 | release draft + `check-latest-json` + 手动 publish | 避免构建未完成就暴露 latest.json；可审计 | 直接 publish；floating action | T-011 |
| D-010 | 首版仅 macOS universal（已确认） | 聚焦 Xcode 签名/公证；避免跨平台 key/安装分支 | 平台覆盖较窄；Windows/Linux 需后续版本 | T-011；`NEXT-AU-007` |
| D-011 | 版本单一源检查（7 处 + Cargo.lock） | 避免版本漂移 | 只信 tauri.conf | T-002 |
| D-012 | 新增 6 个 `AppErrorCode` + 结构化 details | 前端可区分重试/签名/不支持 | 字符串解析 | T-004 |
| D-013 | 4 命令 + 2 事件 + 4 capability，走 contract 单一源 | 防漂移；契约测试可锁定 | 组件直接 invoke | T-004/T-005 |
| D-014 | 新增独立 `UpdatePort`，不污染 `IpcPort` | 文档通道与更新通道职责分离 | 扩展 IpcPort | T-005 |
| D-015 | UI：命令面板 + 非模态横幅 + 安装对话框；不加设置/关于页 | 现有表面复用；范围最小 | 设置页/原生菜单 | T-009 |
| D-016 | 发布说明纯文本渲染 | 防 XSS；无需 sanitizer 依赖 | Markdown HTML 渲染 | T-009 |
| D-017 | 不自动重试下载；失败后用户显式重试 | 进度/错误语义确定；避免隐藏循环 | 指数退避自动重试 | T-007 |
| D-018 | 进度累计 chunk + 100ms 节流 + 最终 100% | 插件回调是 chunk 长度；避免 IPC 洪泛 | 直接把 chunk 当累计（Go-Sitech bug） | T-006/T-007 |
| D-019 | 安装中忽略关闭；安装前 flush；macOS 调 `request_restart` | 防二次退出/丢数据；MVP 仅 macOS | `app.restart()`/`app_close_confirm` 重启 | T-007/T-009 |

| D-022 | `CloseGuard` 增加安装门闩（同一 Mutex） | 消除 `pending`/`Installing` 的 check-then-act 竞态；关闭门仍唯一 | 只在前端/命令层检查 | T-007 |

### 10.2 回滚方案

| 场景 | 回滚方式 | 验证 |
|---|---|---|
| 代码缺陷 | revert 对应 commit；不 force push main | `pnpm ci:local` |

| 签名密钥泄露 | 停止发布；按 03 §5 轮换；评估旧客户端 | 新 key 过渡发布 |
| 配置错误 | 回滚 tauri.conf/Cargo；重建 | `cargo check`/build |
| CI secret 泄露 | 轮换 secret；审计日志；最小权限 | 重新跑 release |
