## 1. 实施结论

当前代码已经具备原子写、冲突检测、历史、回收站、工作区 jail、搜索索引和会话恢复，但跨这些能力仍有三类结构性问题：

1. **文档身份不存在**：`DocToken` 是每次打开生成的 UUID（`document_registry.rs:12-24`），历史、视图状态、搜索索引、`windows.json` 全部按 canonical path 派生键；原子保存会更换 inode，外部 rename 会改变 path，因此“保存后换身份”和“重命名后丢历史”是同一根因。
2. **边界与恢复语义不一致**：打开上限 10 MiB、写入上限 16 MiB（`file_service.rs:11-15`），10 MiB + 1 字符保存成功后无法重新打开；搜索索引仍按 10 MiB，watcher 对 10–16 MiB 不 hash；回收站恢复跨卷/Windows 语义不完整。
3. **路径安全与所有权仍是 check-then-use**：`canonicalize + starts_with` 后到 `open/rename` 之间没有句柄级身份复核；`write_atomic`、`reload`、`history_*`、`save_image` 只查 registry，不查窗口归属；`DocumentWatcher` 全局广播带 token 的事件。

推荐路径是 **一个权威 DocumentId + 一个 FileIdentity 复核原语 + 一个统一文档上限**，复用现有 `DocumentRegistry`、`AtomicWriter`、`FileLockStore`、`HistoryStore`、`SessionStore`、`SearchIndexService`、`WorkspaceWatcher`、`TrashStore`，不新增第二套写盘、第二套 watcher、第二套路径解析。

最小安全切片是 `T-001 → T-002 → T-004 → T-005 → T-006 → T-008`；边界（T-003）、token（T-007）、trash（T-009）、前端树（T-011）可在文件不冲突时并行。明确不做：完整 `openat2`/Windows 句柄级 root jail、在用户文件中写 ID、跨重启全盘扫描、系统回收站、新增用户配置或 SQL 表。

R14 已通过；Q-001 ~ Q-008 已于 2026-11-09 全部批准（Q-001 A、Q-002 A、Q-003 B、Q-004 A、Q-005 A、Q-006 A、Q-007 A、Q-008 B），无附加条件。T-001~T-015 已按本计划实施完成；最终验证与 PARTIAL/B-ID 见 `02 §4/§7/§15`。提交仍需用户明确同意。

## 4. 目标方案

### 4.1 目标链路

```text
document_open
  -> WorkspaceService::resolve_document_verified (root jail + parent identity)
  -> FileService::read_raw(MAX_DOCUMENT_BYTES)   // fstat/O_NOFOLLOW, format+identity
  -> DocumentIdentityStore::resolve_open(path, identity)
  -> DocumentRecord { document_id, paths, io_lock, active, state }
  -> registry.by_path.insert(PathKey, token)

document_write_atomic
  -> WindowSessions::owns_current_document(label, token)
  -> DocumentRegistry::write_atomic
     -> record.io_lock -> paths snapshot -> FileLock(path) -> DocState
     -> FileService::read_raw(MAX_DOCUMENT_BYTES)
     -> history.capture(record.document_id)
     -> write_formatted (dirfd/target 复核)
     -> commit 后 fstat -> identity.bind_save(id, new_file)

外部 rename（文件）
  -> WorkspaceWatcher::handle_events
     -> if index: SearchIndexService::rename_path(root, old_rel, new_rel, prepared) -> Result
     -> DocumentRegistry::rekey_path(old_abs, new_abs, root) -> Result
        -> io_lock -> resolve_rekey_paths -> identity.adopt_many(Some(DocumentId))
        -> return relocated + requires_rescan
     -> WorkspaceWatcher: emit_to owner + allow_document_assets + apply_window_titles
     -> requires_rescan: notify_rescan（raw symlink/detach）

外部 rename（目录）
  -> WorkspaceWatcher
     -> DocumentRegistry::rekey_prefix(old_dir, new_dir, root) -> Result
     -> SearchIndexService::notify_rescan
```

### 4.2 设计决策

| D-ID | 决策 | 理由 | 拒绝方案 | 影响任务 |
|---|---|---|---|---|
| D-001 | 统一 `MAX_DOCUMENT_BYTES = 16 MiB`，打开/保存/索引/watcher 共用 | 消除“保存成功但重开失败”；16 MiB 是现有写入承诺 | 保留 10/16 双上限；保存后阻断 | T-003 |
| D-002 | 新增 `DocumentIdentityStore`（JSON，UUID），DocumentId 与 path 分离 | 原子保存换 inode，纯 inode 派生 ID 不稳定；持久 ID 才能跨 save/rename/restart | 纯 file ID；path hash；写用户文件 | T-001,T-002 |
| D-003 | live `DocumentRecord.document_id` 权威；History/View 直接接收 ID | 防止 use-time `observe(path)` 抢 ID；路径复用不串桶 | 每次使用时 observe | T-005,T-006 |
| D-004 | rekey 用 `adopt` 保留原 ID，不 `observe` 新 ID | 外部 rename/原子保存后历史/视图不失联 | observe(new) | T-005,T-008 |
| D-005 | 文件锁保持 path-hash | 跨版本、identity 故障时仍互斥；rename 后新 path 锁 | 锁改 DocumentId | T-005 |
| D-006 | verified read 用 O_NOFOLLOW/fstat；write 用 dirfd fstat + target 复核 | 真正缩 TOCTOU；不依赖第二次 path 解析 | 仅 canonicalize；信任 crate | T-004 |
| D-007 | Save As 释放 current+previous；mutating 只认 current | 关闭 token 泄漏与跨窗口访问 | 只修 Save As；全局广播 | T-007 |
| D-008 | 文件/目录 rename 都 rekey；目录前缀 | 覆盖真实场景 | 只处理文件 rename | T-008 |
| D-009 | symlink 文件按 link path 索引，仅 root 内 | 树/索引一致，避免外部内容入索引 | 隐藏所有 symlink；跟随目录 | T-008 |
| D-010 | trash hard_link/copy + trusted roots + 流式 | 跨卷/防越界/防 OOM | 直接 rename；信任 app data | T-009 |
| D-011 | 不新增用户配置/SQL 表；唯一新增数据文件为 `identity/documents.json`（Q-002） | 满足“新增配置/表需人工同意” | 新增 settings；identity SQLite | T-002 |
| D-012 | `windows.json` 增加可选 `documentId`；恢复校验身份 | 运行期/重启 rename 恢复 | 只存 path；存 token | T-005,T-006 |
| D-013 | Windows/Linux 采用“定向 cargo test + compile”而非全量真机 | 现有 CI 结构可扩展，成本可控 | 只 compile；要求全部真机 | T-013 |
| D-014 | identity store 为 `None` 时完全使用 legacy 键（history path-hash、view path、lock path-hash） | Windows/回滚安全；不生成非法/孤立键 | `p:<hex>` 伪 ID | T-002,T-006 |
| D-015 | 虚拟树首帧 560px + 离屏 focusRow + aria-current/type-ahead | 10k 首帧 DOM 有界、键盘/VoiceOver 可达 | 全量渲染 10k 行 | T-011,T-012 |
| D-016 | IdentityStore 用 live 快照 + 多值 by_file + legacyPaths + candidate-first；degraded 写 API 返回 `IDENTITY_DEGRADED` | 防 live ID 重绑/hardlink 串桶/先 bind 后 persist；降级不写半映射 | 单值 by_file、先内存后落盘 | T-002,T-005,T-006 |
| D-017 | write_formatted 接收 ExpectedTarget（identity 可空）+ parent_identity，返回 WriteOutcome | 锚定 read_current 身份；temp 句柄提供 commit 后身份 | 只按 path 覆盖 | T-004,T-010 |
| D-018 | WorkspaceWatcher 通过 WorkspaceEventSink 通知，不直接依赖 DocumentWatcher | 打破 DR↔DW 环；保留 targeted emit/assets/titles | watcher 直接持有另一 watcher | T-008 |
| D-019 | trash trusted roots 只在 workspace open 时恢复；同卷/EXDEV 都 hash；symlink 删除 link 本身 | 防 roots=[] 被 is_dir 兜底；完整性；symlink 语义 | 同卷不校验、删除 target | T-009 |
| D-020 | symlink raw/canonical 分离：raw 只做索引别名，canonical 做正文/History/Lock/资产；target rename 后 raw 悬空或身份不匹配则 detach，canonical 身份不匹配则 Conflict；不重写用户 symlink | 避免 watcher 修改用户文件系统；防旧 target 重建后改绑 ID；L-017/NEXT-013 | 自动修复 link 的用户体验 | T-008 |
| D-021 | release 持 `rekey_lock`；close 先 deactivate（drop io_lock）再 release | 防 release/rekey 并发留下 stale by_path；避免 ABBA | 关闭多一次短锁 | T-005,T-007 |
