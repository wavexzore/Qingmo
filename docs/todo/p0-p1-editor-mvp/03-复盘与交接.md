## 1. 最终结论

本阶段已从纯方案进入可运行骨架：T-001 建立了 pnpm workspace、Vite 7/React 19/TS 5 桌面前端、Tauri 2 Rust 空壳与两个基线 tag；T-002 收紧了窗口、CSP、asset protocol 与 core 权限；T-003 冻结了 DTO、错误码、4 条命令 + 1 个事件和 ts-rs 生成契约；T-004 落地了 UI token、App Shell、i18n、状态栏与 CommandRegistry；T-005 打通了 Rust 原生 dialog、单文档 token、严格编码/EOL 与 10MiB 读取；T-006 建立了唯一原子写、always-hash 冲突与 UTF-16/CRLF 字节级保存。它验证了“可安装、可构建、可启动、可测试、权限面最小、契约可执行、UI 基础可用、读取不产生乱码、保存不半写”，但**还没有验证编辑器闭环**。

方案冻结的四个高风险假设仍未实测：CM6 `EditorState` 是唯一文档真源；Tauri 自定义命令是唯一文件通道（Rust dialog + token）；原子写 + `expectedCurrentHash` 冲突检测不丢字；视口级 Live Preview 在 10MiB 文档上可退化。`02` 的 `VERDICT` 仍为 `PARTIAL`，原因是 6/20 任务完成，而不是发现了实现缺陷。

下一步是 T-007 IpcPort/PlatformPort。T-007 后继续 T-008~T-012；T-012 完成后必须重跑 GitNexus，把 `call_chain_status` 从 `partial` 提升或保留并说明原因。

> 版本/目录差异：T-001 实际采用 React 19.3.1 与仓库根 `src-tauri/`，与文档中的 19.2.9 / 蓝图 §4.2 目录示意不同；已记录在 `01 §13`、`02 §8`，T-020 统一或补 ADR。

## 5. 回滚指南

| 场景 | 回滚动作 | 验证命令 | 风险 |
|---|---|---|---|
| 方案被否决/范围改变 | 删除 `docs/todo/p0-p1-editor-mvp/` 整个目录；不改其他文档 | `ls docs/todo` | 无（未提交代码） |
| T-001 骨架不可用 | `git reset --hard p0-docs-baseline`；不要直接删除未跟踪目录 | `git status` + `pnpm tauri dev` | 可能误删用户后续新增文件，需先确认 |
| 保存丢字/自动保存故障 | 先停写（kill-switch/禁用保存入口）；备份当前文件；回退 `SaveCoordinator`/`AtomicWriter` 变更 | Rust/TS 保存测试 | 用户需手动 Cmd+S；已写错的文件需从备份恢复 |
| 原子写平台失败 | 回退 `AtomicWriter` 到 `tempfile + fs::rename + fsync`，接口不变 | `cargo test --test atomic_writer` | 平台边界需补测 |
| capability 过宽/过窄 | 回退 `capabilities/default.json` + `build.rs` | 契约测试 + 负例 | 过宽会扩大攻击面 |
| 主题/UI 回归 | 回退主题/UI 提交；不影响文件 | 组件测试 | 无数据风险 |
| 版本不兼容 | 回退 `pnpm-lock.yaml`/`Cargo.lock` 到 T-001 基线 | `pnpm install --frozen-lockfile` + `cargo check` | 可能失去新修复 |
| 清理主题偏好 | 删除 localStorage `qingmo.ui.theme` | DevTools/应用启动 | 无（回退 system） |

不可逆变更：**无数据库/schema 迁移，但用户文件写入和 localStorage 主题键是持久化变更**。P1 不建库、不迁移文件、不写系统设置；代码回滚不能撤销已写错的文件。
