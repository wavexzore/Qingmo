## 4. 任务执行协议

每个 `T-###` 严格按以下顺序：

```text
读取任务与依赖
  -> 确认 Q 门禁已满足
  -> Pre-Implementation Check（文件/调用链/版本/命令）
  -> 限定 Files 范围
  -> 实施最小切片（不做 Out of Scope）
  -> 运行 Verification
  -> 在 02 §3 追加执行日志（命令、退出码、关键输出）
  -> 更新 01 §6 的 Status/Evidence/CompletedAt
  -> 更新 README LLM-STATE
```

禁止：

- 没有命令输出/测试结果就把任务标 `done`。
- 跳过 `DependsOn` 直接做下游任务。
- 修改 `Files` 之外的文件且不记录原因。
- 在 P1 引入 SQLite、settings.json、fs/shell/http 插件、插件 SDK。
- 用 `fs::write` / `std::fs::write` 直接落盘绕过 `AtomicWriter`。
- 在 React 组件/Store 中保存正文（`content`/`markdown`/`doc` 字符串）。
- 在组件内直接 `invoke` 绕过 `IpcPort`。
- 遇到失败后反复尝试同一方法而不记录 `B-###`。

## 5. 状态与证据

### 5.1 状态枚举

- 功能：`todo | in_progress | blocked | partial | done | rolled_back | cancelled`
- 任务：`todo | in_progress | blocked | done | skipped`
- 验证：`not_run | pass | fail | partial | skipped`

### 5.2 证据最低要求

| 任务类型 | 最低证据 |
|---|---|
| Rust 服务/命令 | 测试文件路径 + `cargo test <filter>` 输出 + 关键断言 |
| TS 逻辑 | 测试文件路径 + `pnpm test <filter>` 输出 |
| UI | 组件测试或 E2E + 截图/手动记录 |
| 安全/契约 | 契约测试 + 负例（移除权限应失败） |
| 性能 | `bench/results/<date>.json` + 摘要，不写“感觉快” |
| 文档 | 文档路径 + 链接/ID 一致性检查 |

### 5.3 证据记录位置

- 调研/调用链/校准：`02 §3` 的 `E-###` 表。
- 命令：`02 §4` 的 `C-###` 表。
- 失败：`02 §7` 的 `B-###` 表。
- 计划偏差：`02 §8`，并同步 `01 §13`。
- 验收：`02 §5` 的 `AC-###` 表。

## 8. 失败与回滚

1. 失败先记录 `B-###`：命令、退出码、错误、已尝试、下一动作。
2. 连续两次同类失败：停止重试，改为缩小范围或换实现，并在 `01 §13` 记录。
3. 任务无法完成但下游可继续：标记 `blocked`，不得标 `done`。
4. 回滚以任务为单位：回退该任务新增文件/改动，保留接口与测试。
5. P1 无数据库/配置迁移；回滚不影响用户文件。

---

## 9. 复审协议

- 方案阶段至少三轮：R1 架构一致性、R2 Tauri 安全与 CM6 性能、R3 测试拆分与交付。
- 复审只读文件、不改文件；发现写入 `05-多轮评审记录.md` 的 `F-###`。
- 每个发现必须有处置：`accepted`（回改文档/计划）、`rejected`（理由）、`deferred`（NEXT/Q）。
- 回改后更新 `01 §14` 与 `04 §21` 的版本/变更日志。
- 实施阶段每完成 5 个任务或修改契约/保存/路径算法时，追加一次针对性复审。

## 10. 停止条件

满足全部条件才可把 `status` 置为 `done`：

1. Q-001~Q-015 已于 2026-10-26 全部按推荐确认，相关结论见 `01 §12`。
2. `T-001 ~ T-020` 全部 `done` 或有用户批准的 `skipped`。
3. `02` 的 `AC-001 ~ AC-015` 全部 PASS 或有明确 PARTIAL 理由。
4. 全量命令通过（C-999），或 CI 等价通过。
5. `02` 最终 `VERDICT: PASS`。
6. `03` 交接清单完成，回滚/限制/NEXT 已写明。

任一不满足：只能 `partial` 或 `blocked`，不得 `done`。
