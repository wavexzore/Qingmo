## 1. 实施结论

T-001 启动前，Qingmo 不是 Git 仓库，只有 `README.md`、`docs/BLUEPRINT.md`、`docs/RESEARCH.md`、`docs/TOPOLOGY.md` 和拓扑图文件；没有任何 `apps/`、`packages/`、`src-tauri/` 代码。因此本计划的第一条任务是建立可运行骨架，而不是修改既有实现。T-001 已完成，现状见 `02 §3`。

推荐路径是**一条垂直切片**：P0 工程骨架 + P1 编辑闭环（打开、编辑、最小 Live Preview、原子保存、自动保存、冲突检测、主题、命令面板）。它同时验证四个高风险假设：CM6 作为唯一文档状态、Tauri 自定义命令作为唯一文件通道、原子写/冲突检测不丢字、视口级装饰在大文件上可退化。

这是最小风险方案，因为：

1. 不引入 SQLite、插件宿主、文件树、搜索、watcher、恢复表；这些留给 P2/P3，避免在未验证核心链路前扩大 schema 和权限面。
2. 手动保存与自动保存从第一天共用 `SaveCoordinator`，不会在 P2 出现第二套保存逻辑。
3. 文件 IO 只走自定义命令，不启用 `tauri-plugin-fs`；dialog 在 Rust 侧，前端只拿 `docToken`，不接受任意路径。
4. 主题只走 CSS 变量 + CM6 `Compartment`，不建 `settings.json`，避免多套配置源。
5. 命令名/事件名/能力白名单/DTO 有契约测试，P3 插件命令只能接入同一注册表。
6. 关闭统一走 Rust CloseGuard，覆盖红叉/Cmd+Q/Dock Quit，避免 Cmd+Q 绕过 flush。

明确不做：工作区根、文件树、搜索/反链/标签、SQLite、watcher、崩溃恢复/备份、Preview 面板、图片/表格/Mermaid/KaTeX/Shiki、插件 SDK/Host/市场、设置页、原生菜单/托盘/更新器、协作。

Q-001~Q-015 已于 2026-10-26 由用户全部采纳推荐项（见 `01 §12`）；LLM 可直接从 `T-001` 开始，不再等待门禁确认。

## 4. 目标方案

### 4.1 目标链路

```text
用户点击“打开文件”
  -> IpcPort.documentOpen()
  -> Rust document_open（Rust 侧 dialog）
  -> DocumentRegistry: 扩展名/大小/编码校验 -> canonicalize -> 读字节/hash
  -> 生成 docToken；FilePayload（text LF-only）
  -> EditorSession: EditorState.create({ doc, extensions: [readOnly facet] })
  -> EditorHost: 唯一 EditorView + LivePreview ViewPlugin + Theme Compartment
  -> 用户输入 -> CM6 transaction -> EditorState 更新 -> session 派生 dirty
  -> SaveCoordinator.schedule()
  -> 800ms 去抖 / 5s 上限 / 单飞 / flush 循环
  -> IpcPort.documentWriteAtomic({docToken, text LF-only, expectedCurrentHash?})
  -> Rust: 读当前字节/hash -> 冲突检查 -> encode（UTF-16 手写）-> atomic-write-file
  -> SaveResult -> registry 更新 base_hash/size/mtime -> 前端展示镜像（size/mtime）-> clean
```

| 场景 | 回滚方式 | 验证 |

| 用户文件已被错误保存 | 代码回滚不能撤销；从备份恢复；记录事故与编码/EOL 证据 | 字节级对比 |
