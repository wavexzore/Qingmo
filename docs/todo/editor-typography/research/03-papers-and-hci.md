# 论文与 HCI 证据：字号、行高、行长、字体族

> **功能 ID：** `editor-typography`
> **采集日期：** 2026-11-04
> **方法：** Exa 检索论文摘要/全文 + 出版方 DOI 页面交叉核对。
> **限制：** 这些研究主要来自网页/手机阅读，不是 Markdown 编辑器；结论用于确定“合理范围与默认值”，不用于宣称某个像素值对所有人都最优。

## 1. Rello, Pielot & Marcos (2016) — 字号与行距

| 项 | 内容 |
|---|---|
| 标题 | *Make It Big! The Effect of Font Size and Line Spacing on Online Readability* |
| 作者 | Luz Rello, Martin Pielot, Mari-Carmen Marcos |
| 会议 | CHI 2016 |
| DOI | `10.1145/2858036.2858204` |
| 全文 | <https://pielot.org/pubs/Rello2016-Fontsize.pdf> |

### 1.1 实验设计

- 104 名参与者。
- 材料：Wikipedia 文章（text-heavy website）。
- 字号：10–26 pt。
- 行距：0.8–1.8（Arial）。
- 采用 hybrid-measures design，同时测量客观阅读指标与主观可读性、理解题。

### 1.2 主要结论

1. 可读性（以平均注视时长衡量）随字号增大显著提升。
2. 理解题在 18 pt 与 26 pt 条件下正确率显著更高。
3. 行距只有边际效应；两个极端（0.8 与 1.8）都会损害可读性。
4. 作者建议：以“易读”为目标的文本型网站应使用 **18 pt 或更大**，并使用默认行距。

### 1.3 对青墨的含义

- 18 pt ≈ 24 px（96 dpi）。本方案的字号范围 `12–30 px` 必须包含 24 px，否则用户无法到达研究推荐的阅读尺寸；这也是上限取 30 而不是 24 的原因之一。
- 默认 15 px（11.25 pt）低于 Rello 的推荐值，但青墨当前默认是代码编辑器式 mono 正文；首版保持默认外观，把“更大字号”作为用户可选项，避免升级时静默改变所有文档的排版。
- 行距 1.75 高于 WCAG 1.4.8 的 1.5 下限；Rello 的 1.8 极端值提示“越大不一定越好”。本方案不把行高暴露给用户，保持现有 1.75；若未来要加行高，应单独做可用性测试（见 Q-004）。

## 2. Dyson (2004) — 行长以字符数为关键变量

| 项 | 内容 |
|---|---|
| 标题 | *How physical text layout affects reading from screen* |
| 作者 | Mary C. Dyson |
| 期刊 | Behaviour & Information Technology, 23(6), 377–393 |
| DOI | `10.1080/01449290410001715714` |
| 全文 | <https://stu.westga.edu/~ssynan1/literacy/Dyson.pdf> |

### 2.1 主要结论

1. 行长研究里，**每行字符数**比物理行长/视角更能解释阅读差异；眼跳幅度以字符数计。
2. 多项研究显示：长行（可达 100 字符/行）阅读更快，理解率基本不变；短行（25 字符/行）更慢。
3. 但读者主观偏好中等长度，约 **55 字符/行** 被认为最易读；客观速度与主观偏好不一致。
4. 没有可靠证据支持某一个“唯一最优”布局；边距、滚动、屏幕眩光等会混淆结果。

### 2.2 对青墨的含义

- 行长不是本功能的变量；本方案不改行宽，避免把“字号”与“行长”两个变量混在一起。
- **事实校准：** 青墨当前编辑器并没有启用 72ch 行宽。`packages/ui/src/tokens.css:180` 定义了 `--qm-content-max: 72ch`，但 `apps/`、`packages/` 中没有消费点；编辑器只有左右 20px 的 writing inset（`packages/editor-core/src/extensions/theme.ts:35-45`）。
- 因此本方案不能声称“保持 72ch”。行长限制是独立缺口，列入未来工作（Q-004）。
- 如果未来做行长，应以“字符数”而不是固定像素为目标，并同时提供“更快阅读（长行）”与“更舒适偏好（约 55–80 字符）”的取舍。

## 3. Zhu, Su & Dong (2021) — 简体中文手机阅读

| 项 | 内容 |
|---|---|
| 标题 | *Effects of the Font Size and Line Spacing of Simplified Chinese Characters on Smartphone Readability* |
| 作者 | Shangshang Zhu, Xinyu Su, Yenan Dong |
| 期刊 | Interacting with Computers, 33(2), 177–187 |
| DOI | `10.1093/iwc/iwab020` |

### 3.1 实验设计

- 115 名参与者。
- 设备：5.9 英寸智能手机。
- 字号：10、12、14 pt。
- 行距：1.25F、1.5F、2F（F 为字号倍数）。
- 任务：中文文本理解 + 5 点主观偏好。

### 3.2 主要结论

1. 字号与行距都显著影响阅读时间。
2. 只有字号显著影响阅读正确率。
3. 字号、行距及其交互显著影响“阅读难度”和“视觉疲劳”。
4. 中大字号 + 大行距更舒适；小/中字号 + 大行距更有吸引力。

### 3.3 对青墨的含义

- 中文阅读对字号与行距都敏感，不能只用拉丁文研究外推。
- 但该研究是 5.9 英寸手机、10–14 pt；青墨是桌面编辑器，范围 `12–30 px`（约 9–22.5 pt）覆盖并超过其实验范围，不能声称“直接验证了桌面 15 px”。
- 该研究支持“保留较大的 1.75 行距”，也支持“把字号选择权交给用户”。
- 首版不做行高 UI 是范围控制，不是否认行高的重要性；列入 Q-004。

## 4. Beymer, Russell & Orton (2008) — 衬线 vs 无衬线

| 项 | 内容 |
|---|---|
| 标题 | *An Eye Tracking Study of How Font Size and Type Influence Online Reading* |
| 作者 | David Beymer, Daniel M. Russell, Peter Z. Orton |
| 会议 | BCS HCI 2008 |
| DOI | `10.14236/ewic/hci2008.23` |

### 4.1 实验设计

- 82 名参与者，between-subjects。
- 字号：10、12、14 pt。
- 字体：Georgia（serif） vs Helvetica（sans-serif）。
- 指标：阅读速度、注视时长、回扫、理解后测。

### 4.2 主要结论

1. 小字号导致显著更长的注视时长；阅读速度有变慢趋势，但未达显著。
2. 衬线 vs 无衬线：**没有统计显著差异**；Georgia 的第一遍阅读速度约快 7.9%，但不显著。
3. 理解与保持率也没有显著字体类型差异。
4. 作者认为二者在视觉上很相似，结果不意外；字体选择应结合媒介与偏好。

### 4.3 对青墨的含义

- 提供 mono/sans/serif 三个预设是**偏好能力**，不能宣传“serif 更护眼”或“sans 更快”。
- 默认 mono 是产品身份与现状，不需要用论文证明它最优。
- 字体族切换不应改变字号、行高、代码块字体；这些是独立变量。

## 5. WCAG 2.2 的规范约束

详细原文见 [`01-official-docs.md`](01-official-docs.md) §4。这里只列与排版默认值相关的结论：

| 条款 | 要求 | 青墨现状 | 本方案 |
|---|---|---|---|
| 1.4.4 Resize Text (AA) | 文本可放大到 200%，不丢内容/功能 | 应用内无 zoom 命令；Tauri WebView 的 Cmd+plus/捏合缩放未验证 | 增加应用内 12–30px 直接支持；不宣称 Settings chrome 整体合规 |
| 1.4.8 Visual Presentation (AAA) | 行长 ≤80 字符（CJK 40）；行距 ≥1.5；可 200% 放大且不横向滚动 | 行距 1.75；`lineWrapping` 开启；行长未限制 | 仅保证行距下限 + 不横向滚动；不声称整体满足 1.4.8 |
| 1.4.12 Text Spacing (AA) | 用户覆盖行高 1.5×、段距 2×、字距 0.12×、词距 0.16× 时不丢内容 | 普通 CSS；Tauri 无用户样式表机制；未做覆盖测试 | 不宣称满足；只保证不写死 px 行高，继续无单位 1.75 |

> **结论边界：** 本方案是“字号可调 + 字体族偏好”，不是 WCAG 1.4.4/1.4.8/1.4.12 的整体合规改造。行长、段距、字距、Settings 自身缩放、真实 WebView zoom 都仍是独立缺口。

## 6. 综合推断（明确标注为推断）

| 设计选择 | 证据强度 | 推断 |
|---|---|---|
| 默认 15px | 中 | 保持现有外观，避免升级静默变化；低于 Rello 18pt 推荐，但用户可调 |
| 范围 12–30px | 中 | 下限覆盖小字号偏好；上限 30px（22.5pt）超过 Rello 24px 推荐点，留出余量 |
| 步进 1px | 弱 | 19 个离散值足够精细，避免连续滑杆带来的高频重排 |
| 默认 mono | 产品决策 | 保持青墨“纸面 + 代码编辑器”身份；不是论文结论 |
| 保留 1.75 行高 | 强（WCAG）+ 中（Rello/Zhu） | 满足 AAA 下限；Rello 提醒 1.8 极端值，但 1.75 是现有产品值，首版不改 |
| 提供 serif/sans | 中 | Beymer 说明无显著性能差异，作为偏好安全 |
| 不做行高/行长/zoom | 范围决策 | 避免多变量混淆；行长是现有真实缺口，单独立项 |

## 7. 研究限制

1. 没有一项研究直接测试“Markdown 编辑器 + 中文/英文混排 + 代码块”的组合。
2. Rello 使用 Arial 与 Wikipedia，不能直接外推到 mono 正文。
3. Zhu 是 5.9 英寸手机、10–14pt；桌面外推需谨慎。
4. Dyson 是综述性论文，包含多项实验，具体条件不完全一致；“长行更快”不是无条件规律。
5. 字体族的“偏好”与“性能”是两件事；本方案只承诺偏好，不承诺性能提升。
6. 所有结论都需要在青墨真实 WebView 中做一次可用性/可读性验证（列入实施后的观察项，不作为首版门禁）。
