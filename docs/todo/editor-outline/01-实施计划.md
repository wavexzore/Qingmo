## 1. 实施结论

青墨已经有 CM6 单一文档状态、Live Preview、`[TOC]` 占位符、标题锚点、右侧 minimap 和完整的保存/重载/主题/语言链路，但没有持续可见的文档结构导航。`[TOC]` 只在 Live Preview 中出现，Source 模式没有等价入口。用户要求参考 Typora 的左侧大纲面板。

推荐实现是：

1. 在 `editor-core` 新增 `headingOutline` StateField，作为 TOC、标题锚点、侧栏的唯一标题模型；放在 `createEditorState` 基座，确保 Source/Live Preview 都存在。
2. 新增 `outlineParseDriver` ViewPlugin，用 8ms 空闲切片把语法树推进到 200k units 扫描上限；字段只监听 `docChanged || syntaxTree !==`，避免初始 3000 units 导致长期缺标题。
3. `EditorSession` 增加独立的 `getOutlineSnapshot/subscribeOutline/revealPosition`；标题文本不进入 `EditorSessionSnapshot`；通知 100ms trailing；顺手修复 StrictMode attach→detach→attach 的 update listener 重复。
4. 左侧 `OutlinePanel` 只渲染纯文本标题，点击复用 CM6 selection + `scrollIntoView`；默认隐藏，通过命令面板与原生“显示 > 大纲”打开。
5. 不新增持久化配置、DB、Rust 命令或第三方依赖；回滚只需移除面板渲染/命令注册。

明确不做：文件树、大纲内搜索/过滤、折叠/展开、拖拽排序、自动编号、Typora 式视口滚动高亮、Markdown 富文本、代码块内符号、slug 冲突修复、默认快捷键。

实施尚未开始：T-001~T-009 全部 `todo`，T-010（文件树）`skipped`（Q-001=A）。Q-001~Q-007 已全部确认 A，下一步从 T-001 开始。

## 4. 目标方案

### 4.1 目标链路

```text
EditorSession 构造函数
  -> createEditorState({ extraExtensions })
     -> basicExtensions + markdownExtensions
     -> headingOutline (StateField)
     -> outlineParseDriver (ViewPlugin)
  -> EditorHost new EditorView
     -> 初始 3000 units
     -> outlineParseDriver 空闲 forceParsing 到 200k
     -> headingOutline 在 treeChanged 时重建
  -> [TOC] / anchors / OutlinePanel 共享字段
  -> OutlinePanel 点击
     -> EditorSession.revealPosition(lineFrom)
     -> view.dispatch(selection + scrollIntoView)
```

### 4.2 设计决策

| D-ID | 决策 | 理由 | 拒绝方案 | 影响任务 |
|---|---|---|---|---|
| D-001 | `headingOutline` 放 `createEditorState` 基座 | Source/LP 都可用；TOC/锚点共享 | 只在 `livePreview()`/`basicExtensions` | T-002/T-003 |
| D-002 | 字段存 `text` + `plainText` | TOC 保留行内渲染；侧栏/锚点纯文本 | 只存 raw；UI 再解析 | T-002 |
| D-003 | 只取 Document 顶层，排除 frontmatter/details/fence | 与现有 TOC/锚点一致 | 递归所有 Heading | T-002 |
