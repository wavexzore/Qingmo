## 1. 这版方案解决了什么

1. 明确了“缩略图”是 VS Code 式**编辑器全文 minimap**，不是图片/文件缩略图。
2. 找到了唯一最小接入点：`EditorSession.extraExtensions`，而不是 `createEditorState`、`basicExtensions`、`EditorHost` 或 `.cm-gutters`。
3. 解决了 Markdown Live Preview 的几何不均问题：Canvas 与滑块共用 `docYToRail`，锚点只负责估算每行 `docY`，不用行数均分或滚动行程比例。
4. 解决了右侧空间问题：rail 绝对定位在 `view.dom`，`.cm-editor` 右侧 padding 让位，不遮正文、不参与横向滚动、不影响嵌套代码块。
5. 解决了颜色真源问题：抽取 Mermaid 的 `tokenReader` 到共享 `css-color.ts`，不复制 palette。
6. 明确了零新增持久化配置/DB/Rust，回滚只需移除一行扩展注入。
7. 给出了可执行的测试矩阵：纯函数单测、jsdom 生命周期、Playwright 交互/布局/主题/降级、bench。

## 3. 踩坑与纠正记录（方案与实施阶段）

### 3.1 `scrollMargins` 不是布局预留

最初容易把 `replit/codemirror-minimap` 的 `scrollMargins` 当成“给 minimap 让位”的机制。核对 CM6 类型与源码后确认：

- `scrollMargins` 只影响 `scrollIntoView` 等滚动计算；
- replit 真正占宽靠的是 `.cm-gutters` 的 flex 布局；
- 本项目 `.cm-gutters` 被 `styles.css` 强制到左侧 40px，Live Preview 还 `display:none`。

**纠正**：绝对 rail + `.cm-editor` 右侧 padding；不使用 `.cm-gutters`/`scrollMargins`/`.cm-content` padding 做布局。

### 3.2 两套纵轴会让滑块与内容错位

VS Code 的滑块假设源码行高均匀。Markdown Live Preview 的表格、Mermaid、图片是高度不一的 widget，同一段源码行可能占几百像素。如果 Canvas 按行数均分、滑块按像素映射，滑块经过 2000px 的图片时会覆盖大片正文结构，视觉上对不上。

**纠正**：Canvas 与滑块共用 `docYToRail`；锚点只用于估算每行 `docY`，不改变纵轴比例。

### 3.3 replit 的整篇解析不能照搬

`replit/codemirror-minimap` 在文档变化时 `doc.toString()` 后用 Lezer 整篇解析。对本项目 10 万行文档，这会产生不必要的整篇解析成本。

**纠正**：只做 presentation-only 行扫描，不解析 Markdown 语义；debounce + 文本窗口，绘制异常时降级为像素桶。

### 3.4 Obsidian 插件很强，但不能直接移植

`Nymbo/Markdown-Minimap` 约 5.3k 行，依赖 Obsidian API，完整渲染 Markdown DOM。它解决的是“与 Obsidian 渲染完全一致”的问题；本项目不需要。

**借鉴**：锚点映射、滑块最小高度/跨屏平均、让位 margin。  
**拒绝**：DOM 克隆、Prism 高亮、折叠同步、图片渲染、按笔记设置。

### 3.5 主题色不能复制

Canvas 不能直接使用 `var(--qm-*)`。如果复制一份十六进制 palette，会与 `tokens.css` 分叉。

**纠正**：抽取 Mermaid 的 `tokenReader` 到 `css-color.ts`；minimap 只声明语义 token 名，单 token 失败用中性灰，reader 不可用则隐藏。

### 3.6 `.cm-gutters` 不是右侧容器

现有 CSS：

```css
.cm-editor .cm-gutters {
  position: absolute !important;
  left: 0;
  width: 40px;
}
.cm-editor[data-live-preview="true"] .cm-gutters { display: none; }
```

任何加 `.cm-gutters` 类的 rail 都会跑到左侧，并在 Live Preview 消失。**禁止复用该类。**

### 3.7 `EditorSession` 是 CRITICAL，但不是不能碰

GitNexus 显示 77 impacted / 22 processes。方案没有回避，而是把修改限制为“向 `extraExtensions` 数组追加一项”，并先跑基线、加集成测试。这比把 minimap 塞进 `createEditorState` 或 `EditorHost` 更安全，因为后两者会影响更多消费者/生命周期。

### 3.8 性能不是“扫描越快越好”，而是“普通行走快路径”

首版分类器对每一行都跑 fence/table/setext/ATX/rule/quote/list/HTML 正则链，100k 行 Chromium 完整 rebuild CPU p95 在 16~17ms 边缘波动。T-007 的修正不是降上限，而是：

1. 对普通文本行做首字符 + `|` 的快路径，直接标记 text/blank，跳过整条正则链；
2. 把 indent 与 density 合并为一次字符遍历；
3. C-011 用 `cpuMs = scanMs + readMs + writeMs` 门禁，wall time 单独记录（wall 含等待 CM6 `requestMeasure` 的帧调度）。

结果：100k 行、1200 锚点、100k 上限保持不变，CPU p95 降到 **10.80ms**。因此 Q-003=A 不需要降级。

### 3.9 顶部 28px 是 clamp 区，不是 round-trip

`docYToScrollTop(0, pt=28, maxScroll, 0)` 的数学结果是 28，而不是 0。因为 `docY=0` 表示首行顶部（不含 padding），把它放到视口顶部必须加 `pt`；`scrollTop=0..28` 都映射回 `docY=0`，这是不可逆区间。E2E 只断言实际点击落点与标题可见性，没有依赖错误的“0=0”不变量。该偏差记录为 F-046。

## 4. 已知限制

| 限制 | 影响 | 是否接受 | 后续 |
|---|---|---|---|
| 不是字体级镜像 | 字符用 1px 列 + 上下半行墨迹近似，CJK 用 2 列实心块；不是真实字形 | 接受（76px 不可读） | `NEXT-001` |

## 6. 维护指南

### 6.1 调整显示阈值

| 需求 | 改哪里 | 注意 |
|---|---|---|
| 更早/更晚显示 | 视口高度/`MIN_EDITOR_WIDTH` | 同步 E2E-002/018 fixture |
| 支持更大文档 | `MAX_LINES`/`MAX_UNITS` | 先跑 bench；可能需增大 stride |
| 窄窗口也显示 | `MIN_EDITOR_WIDTH` | 检查正文是否过窄 |
| 更宽/更窄 rail | `RAIL_WIDTH` | 同步 E2E reserve/padding 断言 |

### 6.2 增加新的结构类型

1. 在 `MinimapLineKind` 增加 kind。
2. 在分类器/优先级中实现，补 UT。
3. 在 `theme.ts` 增加 token 映射。
4. 在 Canvas 绘制中给 alpha/priority。
5. 在 E2E 像素采样中确认与相邻 kind 可区分。

### 6.3 主题 token 变更

- 只改 `packages/ui/src/tokens.css` 或 `minimap/theme.ts` 的 token 名；
- 不复制 hex 到 Canvas；
- 跑 `theme.test.ts` 与 E2E-006。

### 6.4 性能退化排查

```text
滚动卡顿 -> 检查是否在 scroll 中重绘 Canvas（应只更新 slider）
输入卡顿 -> 检查 debounce/generation 是否失效
长文卡顿 -> 检查 anchors 数量、bucket 数、是否逐行 fillRect
主题切换卡顿 -> 检查是否重建 EditorView（不应该）
```

### 6.5 E2E 维护

- `long.md` 行数变化会影响 E2E-001/003；改 fixture 时同步阈值/断言。
- `note.md` 必须保持不足一屏（默认 1280×720 视口），否则 E2E-002 失效；短但可滚动的场景由 E2E-018 覆盖。
- 新增主题/模式时，补 E2E-006/007。

## 10. 实施结论

- **最终方案成立**：最小侵入、单一真源、可测试、可回滚；R1~R4 评审/冻结完成，Q-001~Q-007 已由用户确认。
- **实施结果**：T-001~T-007、T-009 `done`；T-008 `skipped`；全量 Vitest `595 passed`，minimap E2E `18 passed`，全量 E2E `121 passed / 1 skipped`。
- **性能结果**：100k 行、1200 锚点、100k 上限不变；C-011 CPU p50 8.60ms / p95 10.80ms（wall p50 11.40ms / p95 18.40ms）。保留 Q-003=A，未降 `MAX_LINES`。
- **最大风险已关闭**：`EditorSession` CRITICAL 与布局回归由“只追加扩展 + C-003/C-007 + 回滚演练”控制；回滚只需移除一行注入。
- **实施后偏差**：F-046 `docYToScrollTop(0)=pt`；F-047 事件增加 `cpuMs` 等阶段；F-048 短文档不闪 pending；F-049 扫描快路径；F-050 基线 bare-link title 测试修正；F-051 按用户要求改为 1:1 文本窗口；F-052 增加 Live Preview 渲染块模式；F-053 rail 显示时隐藏原生纵向滚动条并由 slider 取代；F-054 取消 80 行阈值，改为有滚动即显示。详见 `02` §8.1 与 `05` §6.2/§6.3。
- **不要做的事**：直接照搬 replit/Obsidian、使用 `.cm-gutters`、复制 palette、增加第二套滚动/持久化、实施 Q-001~Q-007 未采纳的选项。
